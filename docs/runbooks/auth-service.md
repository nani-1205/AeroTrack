# Runbook: auth-service

**Code:** [services/auth-service/](../../services/auth-service) · **Stack:** Go 1.25+, net/http, pgx, goose, go-redis · **Port:** 7001 · **Schema:** `auth` (role `auth_svc`)

Identity for both portals:
- **Users** sign in with **GitHub OAuth**.
- **Admins** sign in with **username + password**: argon2id hashing, lockout after repeated failures, a bootstrap account, and a forced password change on first sign-in.

The service issues RS256 access tokens (published as JWKS) and rotating refresh sessions stored in Redis. It also records every sign-in attempt and publishes usage events for analytics.

## Configuration (`services.json` → `shared` + `auth`)

| Key | Default | Meaning |
|---|---|---|
| `shared.jwt.issuer` / `userAudience` / `adminAudience` | `aerotrack-auth` / `aerotrack-user` / `aerotrack-admin` | Token claims; the gateway must use the same values |
| `shared.jwt.accessTtlSeconds` | `900` | Access-token lifetime (15 min) |
| `shared.jwt.refreshTtlSeconds` | `604800` | Refresh-session lifetime (7 days) |
| `shared.internalToken` | random | Required on every non-public route |
| `auth.listen` | `0.0.0.0:7001` | Bind address |
| `auth.db.*` | `auth` / `auth_svc` / random | Schema, role and password |
| `auth.github.clientId` / `clientSecret` | empty | From your GitHub OAuth App. **Required in production.** Empty means GitHub sign-in redirects back with `github_not_configured`. |
| `auth.github.callbackUrl` | `http://localhost:8080/api/auth/github/callback` | Must exactly match the OAuth App's callback URL |
| `auth.github.scopes` | `read:user`, `user:email` | `user:email` gives the email fallback when the profile email is private |
| `auth.github.authorizeUrl` / `tokenUrl` / `apiBaseUrl` | GitHub defaults | Overridable (the tests point these at a fake GitHub) |
| `auth.admin.bootstrapUsername` / `bootstrapPassword` | `admin` / random | Creates the first admin, **only when no admin exists** |
| `auth.admin.maxFailedAttempts` / `lockoutMinutes` | `5` / `15` | Lockout policy |
| `auth.admin.minPasswordLength` | `12` | New-password policy |
| `auth.cookies.*` | see the template | Cookie names and paths; `secure: true` is required in production |
| `auth.jwtPrivateKeyPath` / `jwtPublicKeyPath` | `keys/jwt-private.pem` / `keys/jwt-public.pem` | Relative to `config/`. Generated by `npm run setup`; the service refuses to start if the two don't match. |
| `auth.portals.userUrl` / `adminUrl` | `http://localhost:4200` / `:4201` | Where users are sent after GitHub sign-in |

**GitHub OAuth App** (GitHub → Settings → Developer settings → OAuth Apps → New):
- Homepage URL: `http://localhost:4200`
- Authorization callback URL: `http://localhost:8080/api/auth/github/callback`

Then copy the client ID and secret into `auth.github`.

## Run

```sh
npm run dev:auth                                         # go run ./cmd/auth
cd services/auth-service && go build -o bin/auth ./cmd/auth && ./bin/auth
AEROTRACK_CONFIG=/etc/aerotrack/services.json ./bin/auth
```

**Linux release build** (toolchain setup: [Building and running on Linux](README.md#building-and-running-on-linux)):

```sh
./scripts/build-linux.sh auth
# = cd services/auth-service && CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o <release>/auth-service/auth ./cmd/auth
AEROTRACK_CONFIG=/etc/aerotrack/services.json ./release/auth-service/auth
```

The result is a single **static** binary (about 16 MB) with the migrations embedded, so it runs on any x86_64 Linux. The JWT keys are read from `keys/` next to the config file, e.g. `/etc/aerotrack/keys/`.

On startup the service:
1. checks its config;
2. loads the JWT key pair;
3. waits for Postgres;
4. applies pending goose migrations;
5. creates the bootstrap admin if no admin exists;
6. starts listening.

## Test

```sh
cd services/auth-service
go vet ./... && go test ./...
```

- **Unit tests:** argon2id hashing and JWT/JWKS.
- **Integration tests:** need `npm run infra:up`. They use Redis DB 15 and a fake GitHub server, and delete their own rows. They cover the admin lifecycle (lockout, password change, refresh rotation, logout), the GitHub flow (state cookie, single-use state, email fallback), the internal endpoints, and the internal-token requirement.

## API

The paths below are the service's own. Through the gateway they are prefixed with `/api`, except the open and internal ones.

| Method & path | Access | Purpose |
|---|---|---|
| `GET /.well-known/jwks.json` | open | Public signing key (cached 5 min) |
| `GET /auth/github/login` | public | Starts OAuth: state stored in Redis + `aerotrack_oauth_state` cookie → 302 to GitHub |
| `GET /auth/github/callback` | public | Checks state, exchanges the code, upserts the user, sets cookies, 302 to the portal (or `/login?error=…`) |
| `POST /auth/refresh` | refresh cookie | Rotates the refresh token, issues a new access cookie |
| `POST /auth/logout` | refresh cookie | Revokes the session, clears cookies |
| `GET /account/me` | user | Profile of the signed-in user |
| `POST /admin/auth/login` | public | `{username, password}` → admin cookies + `{admin}` |
| `POST /admin/auth/refresh`, `POST /admin/auth/logout` | admin refresh cookie | As for users |
| `GET /admin/account/me` | admin | Admin profile (includes `mustChangePassword`) |
| `POST /admin/account/password` | admin | `{currentPassword, newPassword}`; signs out the admin's other sessions |
| `GET /internal/users/summary` | internal | Totals and active counts, plus signed-in user and admin sessions (analytics) |
| `GET /internal/users?search=&limit=&offset=` or `?ids=a,b` | internal | User directory / lookup (analytics) |

**Error codes returned to the portals:**

| Code | Status | Meaning |
|---|---|---|
| `invalid_credentials` | 401 | Wrong username or password; deliberately identical whether or not the username exists |
| `locked` | 423 + `Retry-After` | Account locked after repeated failures |
| `weak_password` | 422 | The new password breaks the policy |

GitHub failures don't return an error status. The service redirects to the portal's `/login?error=<code>`:

| Code | Meaning |
|---|---|
| `github_not_configured` | No GitHub OAuth App credentials in config |
| `github_denied` | The user cancelled on GitHub |
| `invalid_state` | The sign-in link expired or was already used |
| `github_error` | GitHub couldn't be reached |
| `account_disabled` | The user's account is disabled |
| `server_error` | Something failed on our side |

## Data

**Tables (schema `auth`, migrations in [internal/database/migrations](../../services/auth-service/internal/database/migrations)):**

| Table | Contents |
|---|---|
| `users` | id (UUID v7), github_id, login, name, email, avatar_url, is_active, created/updated/last_login |
| `admins` | id, username (lower-case), argon2id password_hash, must_change_password, failed_attempts, locked_until |
| `login_events` | Every user/admin sign-in attempt: success, reason, IP, user agent |

**Redis keys:**

| Key | Contents |
|---|---|
| `auth:refresh:<sha256(token)>` | Session JSON. Tokens are never stored, only their hashes. TTL = refresh TTL. A rotated token stays valid for a 30 s grace window. |
| `auth:sid:<sessionId>` | Hash of the current token for the session |
| `auth:subject:<user/admin>:<id>` | Set of the subject's session ids |
| `auth:active:<user/admin>` | Sorted set of session id → expiry; drives the "signed in now" counts |
| `auth:oauth-state:<state>` | Single-use OAuth state (TTL 10 min) |

**Events (Redis stream `events:auth`, consumed by analytics):** `user.signup`, `user.login`, `user.logout`, `admin.login`, `admin.login_failed`, `admin.locked`, `admin.logout`, `admin.password_changed`.

## Routine tasks

Run the SQL below in the superuser shell (see [infrastructure.md](infrastructure.md#everyday-commands)).

**Unlock an admin:**
```sql
UPDATE auth.admins SET failed_attempts = 0, locked_until = NULL WHERE username = 'admin';
```

**Reset a forgotten admin password.** There is no self-service reset; the bootstrap path re-creates the account:
1. Set a new `auth.admin.bootstrapPassword` in `services.json`.
2. Delete the account: `DELETE FROM auth.admins WHERE username = 'admin';`. This only re-creates it if **no** admin is left.
3. Restart auth-service. The admin is re-created and must change the password at first sign-in.

**Disable a user.** Their next request returns 401, and sign-in redirects with `account_disabled`:
```sql
UPDATE auth.users SET is_active = false WHERE login = '<github-login>';
```

**Sign everyone out.** Delete the session keys; access tokens still work for up to 15 min:
```sh
docker compose exec redis sh -c 'redis-cli -a "$REDIS_PASSWORD" --no-auth-warning --scan --pattern "auth:*" | xargs -r redis-cli -a "$REDIS_PASSWORD" --no-auth-warning del'
```

**Rotate the JWT signing key:**
1. Move `config/keys/jwt-*.pem` aside.
2. Run `npm run setup`. It only creates the missing key pair and leaves your config files alone.
3. Restart auth-service.

The gateway fetches the new key the first time it sees the new key id. Existing access tokens stop validating, so browsers silently refresh, because refresh sessions are kept.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| GitHub sign-in returns to `/login?error=github_not_configured` | `auth.github.clientId/clientSecret` empty | Create the OAuth App and fill both in |
| GitHub shows "redirect_uri is not associated with this application" | `callbackUrl` doesn't match the OAuth App | Make both exactly `http://localhost:8080/api/auth/github/callback` |
| `/login?error=invalid_state` | The sign-in started in another browser or tab, took more than 10 min, or was refreshed after success | Start the sign-in again |
| `JWT public key … does not match private key` at startup | Mismatched key files | Regenerate both (see the routine tasks above) |
| Admin sign-in returns 423 | Account locked | Wait `lockoutMinutes`, or unlock with SQL |
| `migration failed (… nothing forced)` | An applied migration was edited or removed | Restore the original file; put changes in a **new** migration |
| `requests must come through the gateway` (401) | Called directly without `X-Internal-Token` | Call through the gateway, or send the internal token |
